# Data analysis for &ldquo;Structural Chirality from Short-Range Order in Heteroanionic Materials&rdquo;

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.21799772.svg)](https://doi.org/10.5281/zenodo.21799772)

Authors:
- Benjamin J. Morgan ORCID [0000-0002-3056-8233](https://orcid.org/0000-0002-3056-8233)

## Summary

This repository contains the data and analysis code for &ldquo;Structural Chirality from Short-Range Order in Heteroanionic Materials&rdquo; \[1\].

The dataset contains density-functional energies for a set of anion orderings in NbO<sub>2</sub>F and for a smaller comparison set in TaO<sub>2</sub>F, a cluster expansion model fitted to those energies, and densities of states generated from a series of replica-exchange Wang&ndash;Landau simulations of that cluster expansion across five supercell sizes, together with code to process these data and produce the manuscript figures.

To run the complete data analysis, run the following commands from the top level directory:
```
conda env create -f environment.yml
conda activate nbo2f-chirality
make
```

## Contents

- `README.md`: This file.
- `environment.yml`: Python dependencies, pinned to the versions used for the as-published analysis.
- `Makefile`: The top-level analysis workflow.
- `data`: Density-functional calculations, the cluster expansion and its training set, structure files, and the Wang&ndash;Landau densities of states.
- `workflow`: Analysis and plotting scripts run by the `Makefile`.
- `methods`: Scripts documenting how the cluster expansion was fitted and its training set assembled, and how the 3&times;3&times;6 structures were built and enumerated. These are a record of the method and are not run by the `Makefile`, although `workflow/dft/achiral_3x3x6.py`, `workflow/dft/classes_3x3x6.py` and `workflow/ce/ce_vs_dft.py` use their functions.
- `figures`: Manuscript figures, generated by running the analysis workflow.
- `docs`: Guides to running a simulation and to the cluster-expansion workflow.
- `build`: Intermediate files produced by the `Makefile`. Not included in the repository.

## Data processing workflow

Data processing is managed using `make`, and uses the scripts in the `workflow` and `figures` directories. From the deposited data, the workflow computes the temperature-dependent averages of the structural order parameters, the transition temperatures of each simulation and their extrapolation to infinite system size, the order parameters of each calculated configuration together with their ground-state and random-limit reference values, the ordering of the twelve orbits in r2SCAN against PBEsol, the energies of the TaO<sub>2</sub>F configurations against their NbO<sub>2</sub>F counterparts, the point-charge electrostatic energies of the twelve orbits against their DFT energies, the energies of the stackings of the ground-state ordering against the homochiral one, the enumeration of every arrangement on the 3&times;3&times;6 cell that obeys both ordering rules and its symmetry classes, the energies of every achiral one, the cluster-expansion energies against DFT on the low-energy manifold, in and out of the training set, which of the twelve orbits the iron/vacancy order of &beta;-Fe<sub>2</sub>SeO belongs to, and every plotted manuscript figure. The full analysis can be rerun with:
```
make clean
make
```
The `Makefile` records how each file is produced: every product lists its inputs and the command that builds it. The density-functional and Wang&ndash;Landau results are only ever read; the cluster expansion and its training set are committed, but are rebuilt from those calculations so that the chain from the calculations to the model the simulations sampled is unbroken.

## Data

The density-functional calculations are included in full, as their VASP inputs and `OUTCAR` files. The pseudopotentials are not redistributable; `POTCAR.spec` records which were used.

The Wang&ndash;Landau simulations are included as their stitched densities of states and microcanonical observable moments, rather than as the multi-gigabyte checkpoint files from which those are extracted. These are the starting point for all of the finite-temperature analysis. Regenerating them from a simulation, rather than reusing the deposited files, requires rerunning the sampling; `docs/running-a-simulation.md` describes how. Wang&ndash;Landau sampling is stochastic, so a rerun gives an equivalent density of states rather than an identical one: across the five independent seeds at each size, the transition temperature varies by about 0.2 K.
